# SWPD-WF: Stress-Weighted, Phase-Disaggregated Water-Footprint Model

Reproducible artifact for the IEEE conference paper
"A Stress-Weighted, Phase-Disaggregated Water-Footprint Model for
Hyperscale AI Compute".

The artifact implements Algorithms 1 and 2 from the paper, the
five-claim evaluation plan, and the reproducibility commitment
described in Section V-F of the paper.

## What the artifact delivers

1. **A working Python implementation** of the SWPD-WF model
   (`swpd_wf/model.py`) that takes five public inputs and produces
   the scalar $W(f, r)$ and the six-element attribution vector
   $\mathbf{W}(f, r)$ in a single linear pass.

2. **A frozen snapshot of all five public datasets** (`data/`)
   with SHA-256 checksums so the headline numbers are bit-identical
   to what the paper reports (`data/CHECKSUMS.txt`).

3. **Eleven unit tests** (`tests/test_model.py`) covering Claim C1
   (reconciliation), Claim C2 (phase monotonicity), Claim C5
   (uncertainty structure), bit-identicality, lookup robustness,
   and beta normalisation.

4. **A pre-registered evaluation plan** that is enforced by the
   test suite: the analysis is run, the headline numbers are
   computed, and the result is compared to a known reference
   (`scripts/verify_reproducibility.py`).

5. **All figures** referenced in the paper (`figures/*.pdf`),
   generated by `scripts/make_figures.py` against the same
   snapshot.

6. **A CI workflow** (`.github/workflows/reproduce.yml`) that runs
   the entire pipeline on every push. The status badge is the
   operational evidence for Claim C4 (the model can be
   instantiated from public data without operator disclosure).

## Quick start

```bash
# 1. Create a virtual environment and install dependencies
python -m venv .venv
source .venv/bin/activate    # On Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. Run the unit tests
pytest -v

# 3. Compute the worked example
python scripts/worked_example.py

# 4. Generate all figures
python scripts/make_figures.py

# 5. Pin the reference numbers and verify bit-identicality
python scripts/compute_checksums.py
python scripts/verify_reproducibility.py
```

## Public datasets used

| Slot | Source | License | Used for |
|------|--------|---------|----------|
| 1 | Google Cloud regional WUE | Public (Google sustainability report) | Cooling-class WUE |
| 2 | EPA eGRID + ENE | Public (epa.gov) | Grid water intensity (WIf) |
| 3 | WRI Aqueduct 4.0 | Public, CC-BY | Baseline water stress $S_r$ |
| 4 | IEA *Data Centres and Data Transmission Networks* | Public (IEA) | Embodied water coefficient |
| 5 | Open workload traces (MLPerf, public LLM serving) | Public | Training/inference phase share |

The five input slots of the model are populated entirely from
public, license-clean sources. Operator disclosure is not used
by construction; this is the operational form of Gap 3 in the
paper.

## Re-using the artifact with new data

To re-run the model against a different disclosure year or a new
geographic region:

1. Edit the dataclass constants at the top of `swpd_wf/data.py`
   (the `WUE_DATA`, `EGRID_DATA`, `AQUEDUCT_DATA`, `EMBODIED_DATA`,
   `WORKLOAD_DATA` lists). Each row is a single public input.

2. Re-run `python scripts/compute_checksums.py`. The new SHA-256s
   in `data/CHECKSUMS.txt` will reflect the new snapshot.

3. Re-run `python scripts/verify_reproducibility.py`. The
   reference numbers in `data/REFERENCE_NUMBERS.json` will need to
   be updated to match the new snapshot; this is the deliberate
   re-pinning step.

4. Commit the updated `data/` directory. The CI workflow will
   re-run the entire pipeline against the new snapshot and post
   the result on the status badge.
